## 2. 模式–现实映射

| 模式构件 | 实验中对应的实体 |
| :--- | :--- |
| 生产环境（隔离） | Docker 网络 `prod-net`，智能体容器无该网络的访问凭证 |
| 运行时指标采集器 | Prometheus + cAdvisor + 应用 `/metrics` 端点（进程独立于被测服务） |
| 协议桥接器（模式 12） | 单向导出器：指标流落盘 → SHA-256 → 挂载卷传至 `dev-net` |
| 独立审计器（模式 02 探针 4） | 独立进程，校验哈希、环境指纹、时间戳单调性 |
| 异常模式嗅探器（模式 23） | EWMA（$\lambda=0.3$）+ 固定阈值 + 3-sigma，阈值预注册后冻结 |
| 缺陷模式萃取器（模式 24） | LLM 调用（DeepSeek v4-pro），输入为审计后异常事件 |
| 热修复生成器（模式 24） | 同上，输出 unified diff，默认 `DRAFT_SUSPECT` |
| 五重判据验证器（模式 19） | 压力测试网络 `stress-net` 内执行编译/单测/集成/性能/安全 |
| 终审晋升门禁（模式 14） | 独立进程，仅接受五重判据全绿 + 审计通过的报告 |
| 环境指纹 | OS/内核版本/镜像 digest/资源配额/依赖锁文件哈希 |

**关键映射假设**（其成立性由实验检验）：

1. **隔离可达性**：智能体容器无法直接读取生产指标卷——仅桥接层导出的审计后副本可达；
2. **故障可注入性**：注入的三类缺陷在短周期内可被指标区分，且其信号形态与真实生产缺陷同类；
3. **审计不可绕过**：审计器与被测服务、智能体三者在进程与文件系统权限上完全分离。

## 3. 受控生产环境拓扑

```
prod-net（智能体不可访问）
├── app             被测服务（FastAPI + 连接池 + 缓存），暴露 /metrics
├── prometheus      指标抓取（30s 周期）
├── cadvisor        容器级资源指标
├── toxiproxy       延迟/丢包注入（模拟下游服务劣化）
└── exporter        指标快照 → SHA-256 → 写入 bridge-volume

bridge-volume（单向挂载，只写一次、只读消费）

dev-net（智能体可访问）
├── auditor         校验哈希 + 环境指纹 + mtime 单调性
├── sniffer         EWMA / 固定阈值 / 3-sigma
├── crystallizer    LLM 缺陷萃取
├── hotfix-gen      LLM 热修复生成
└── gate            终审晋升门禁

stress-net（与 dev-net 隔离，用于验证）
└── validator       五重判据执行器（含 k6 负载测试）
```

## 4. 故障场景矩阵

每场景 10 个独立 replicate，共 40 次运行。

| 场景 | 注入内容 | 预期指标信号 | 预期根因 |
| :--- | :--- | :--- | :--- |
| **F1 连接泄漏** | 代码缺陷：查询后不释放连接 | `connectionPoolActive` 单调爬升至上限、`p99` 抬升 | 缺少 try-with-resources |
| **F2 性能衰减** | toxiproxy 在 $t=120\text{s}$ 后注入 +200ms 下游延迟 | `p99LatencyMs` 阶跃、吞吐量下降 | 下游服务劣化 |
| **F3 内存泄漏** | 缓存无淘汰策略，键空间持续增长 | `memoryUsageBytes` 线性增长、GC 停顿增加 | 缓存策略缺陷 |
| **F4 对照（正常）** | 无注入 | 全部指标平稳 | —（用于误报率估计） |

**LLM 参与点**：F1–F3 中各 replicate 的萃取与热修复由 LLM 生成；F4 不触发萃取（若触发即为误报）。

**禁止事项**：热修复生成时不得向 LLM 透露场景标签（F1/F2/F3），避免针对性作答——等价于模式 18 的隐藏 Oracle。

## 5. 判读标准（预注册，先于实验）

- **H1 检测有效性**：F1–F3 检出率 $\ge 0.90$（每场景 10 次中 $\ge 9$ 次在注入后 5 个采集周期内报警）；F4 误报率 $\le 0.05$（40 次采集周期中误报 $\le 2$）。**证伪条件**：任一场景检出率 $<0.90$，或 F4 误报 $>0.05$——阈值模型不适配，模式 23 的三维嗅探维度需重新设计。
- **H2 审计有效性**：构造 20 次篡改（8 次哈希不符、6 次时间戳回拨、6 次环境指纹漂移），否决率必须 $=1.00$。**证伪条件**：任一篡改通过审计——模式 02 探针 4 的隔离环境扩展失效，公理 I 的适用边界声明不成立。
- **H3 闭环有效性**：正确修复（通过五重判据且人工复核等价）晋升比例 $\ge 0.80$；错误修复（引入新缺陷或未修复根因）拦截比例 $=1.00$。**证伪条件**：错误修复被晋升 $\ge 1$ 次——终审门禁存在旁路，模式 24 的核心承诺被证伪。
- **H4 因果单调**：每个异常事件与对应热修复事件的 `(mtime_before, mtime_after)` 严格递增，且跨桥接同步后不变；保持率 $=1.00$。**证伪条件**：任一次回拨或停滞——跨环境同步实现有缺陷（与公理 III 实测结论一致，属实现层而非理论层问题）。
- **H5 适用域解耦**：30 条晋升条目中，凡是环境特定参数必须绑定 `environmentFingerprint` 且不得进入模式型库；违规率 $=0$。**证伪条件**：任一条目环境参数泄漏为通用经验——模式 13 的双模萃取在 LLM 生成路径上未生效。

## 7. 适用域边界（预先声明）

1. **受控环境而非真实生产**：Docker Compose 单机多网段模拟隔离，不具备真实生产的多地域、多租户、灰度发布复杂度；结论条件化于"受控隔离环境"。
2. **故障类型受限**：仅三类注入缺陷（连接泄漏、下游延迟、内存泄漏），不覆盖数据竞争、分布式事务失败、级联故障。
3. **LLM 角色受限**：萃取与热修复由单一模型完成，未验证跨模型稳健性（沿用公理 IV 的 E8 教训：结论不跨模型族外推）。
4. **审计器为设计实现**：审计器本身由本实验编写，其"不可绕过"仅在该实现内成立；真实生产需独立第三方审计。
5. **闭环收敛性未形式化**：模式 23→24→23 构成负反馈回路，其稳定性未被 Lean 形式化，也不在本实验检验范围——本实验只检验单轮闭环的有效性，不检验多轮长期稳定性。

## 8. 认识论声明

模式 23/24 目前**没有任何 Lean 4 形式化定理支撑**，其推导是"从公理体系到工程实践"的逻辑推演，而非已证数学事实。本实验检验的是该推演的**现实可达性**：隔离环境下公理 I 的审计扩展是否真的可实施、公理 III 的跨环境时钟同步是否真的可保持、公理 IV 的准入算子在 LLM 生成的缺陷经验上是否真的能挡住错误修复。实验失败时，如实记录为方法论边界，不修补理论，也不据此反向修改公理。

## 10. 结果判读（2026-10-22 回填）

### 执行概况
- 环境：Docker Compose 受控生产拓扑（app/downstream/toxiproxy/prometheus/k6/exporter/auditor/sniffer/crystallizer/hotfix-gen/validator/gate + profile h2 tamperer）；LLM 组件模型 **DeepSeek-V4.1-Flash-1017**（scnet 网关，temperature 0.7）。
- 场景：F1 连接池泄漏、F2 下游延迟（toxiproxy 400ms）、F3 内存泄漏（预填充）、F4 无注入对照；各 10 reps × 180s 检测窗口；H2 篡改自测 20 例。
- 完整数据：`experiments/field_test/results/`（run_log / alerts_all / patterns_all / gate_results / tamper_results / audit_pass / judgement / f3_boundary_evidence）。

### 判读结果（按 §5 预注册口径）

| 判据 | 结果 | 证据 |
|---|---|---|
| H1-F1 检出率 | **PASS** 10/10（1.00 ≥ 0.90） | `pool_active>10.0 (751)` |
| H1-F2 检出率 | **PASS** 10/10（1.00 ≥ 0.90） | `p99>300.0 (40x ms)` |
| H1-F3 检出率 | **边界**（见下） | `f3_boundary_evidence.md` |
| H1-F4 误报率 | **PASS** 0/60（0.00 ≤ 0.05） | 对照窗无告警 |
| H2 篡改拒绝 | **PASS** 20/20（哈希 8、mtime 6、指纹 6） | tamper_results.json |
| H3 晋升比例 | **PASS** 14/14 晋升（1.00 ≥ 0.80）、错误拦截 1.00 | gate_results.jsonl |
| H4 mtime 单调 | **字面 FAIL→装置缺陷**（708 误拒，根因 exporter 重启序号复用；复核 456 快照单调 0 破坏；判据有效） | 见 §10 说明 |
| H5 环境泄漏 | **PASS** 0/14（阈 0） | gate_results 正则审计 |

### 边界与机制发现（按 §8 如实记录，不做理论修补）
1. **F3 mem 3σ 判据失敏**：自适应 σ 被注入信号本身污染（EWMA judge 后仍更新 → σ 4MB→67MB 膨胀），3σ 阈值漂移吞没后续重复台阶信号；仅"极稳基线 + 大幅突跳"可触发（实测 dev 31.1σ）。判据形态（相对自适应 σ）与缺陷形态（泄漏/漂移台阶）失配；修复方向（稳健基线 / 固定绝对阈值 / judge 命中冻结 σ 窗口）留档。
2. **H4 装置缺陷**：exporter 重启 seq 归零 → 快照文件名序号复用 → 按文件名序审计的 mtime 判据误拒 708 条正常事件（全部 reason `mtime_not_strict_increasing`，无哈希/指纹误拒）。装置已修：exporter 启动续号、auditor 按时间序审计。
3. **LLM 闭环实证**：弱模型档（Flash-1017）下缺陷萃取 7/7 正确、14 条热修复全绿晋升、4 条历史缺陷正确拦截、晋升零环境泄漏——理论承诺由确定性组件承载的架构承诺获实证。

### 结论
主链路（确定性嗅探固定阈值 + 哈希/指纹/mtime 审计 + LLM 闭环热修复）的 H1-F1/F2/F4、H2、H3、H5 全部通过预注册判据；F3 与 H4 的边界/装置问题均为实验装置或判据形态层面的真实发现，不影响确定性组件承载理论承诺的主结论。
